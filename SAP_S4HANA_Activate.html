PHASE 1

Discover

▼
ObjectiveUnderstand business value, build the business case, explore S/4HANA capabilities, decide on edition & implementation approach (Greenfield / Brownfield / Bluefield).

Key Activities

  • Digital Discovery Assessment (DDA) workshop
  • Trial / sandbox system access & demo
  • Business case & value mapping
  • Edition selection (Public / Private / On-Prem)
  • Approach selection (Greenfield / Brownfield / Bluefield)
  • SAP Readiness Check 2.0 (for conversion scenarios)

Key Roles

  • Customer Sponsor / CIO
  • SAP Account Executive & Solution Advisor
  • Enterprise / Solution Architect
  • Pre-Sales Lead
  • Business Process SMEs

Public CloudGreenfield only. DDA scopes against standard SAP Best Practices content; rapid 3–6 month implementations. No code migration.
Private CloudGreenfield, Brownfield (System Conversion) or Bluefield (Selective Data Transition) all supported. Readiness Check mandatory for conversion.
On-PremiseFull flexibility on implementation approach. Customer-provisioned infrastructure sizing required.
Quality Gate Q1 — Discover Exit Business case approved · Edition & approach decided · Scope & high-level architecture signed off · SOW executed · Steering Committee approved kickoff.
PHASE 2

Prepare

▼
ObjectiveMobilize the team, establish governance, set up the project tooling and infrastructure, plan the sprints.

Key Activities

  • Provision Starter / Sandbox system
  • Define Solution Standardization Board (SSB) charter
  • Define test, OCM, training, cutover strategies
  • Sprint & release planning (Realize horizon)

Key Roles

  • Project Manager / Engagement Lead
  • PMO & Workstream Leads
  • Solution Architect
  • OCM Lead
  • Steering Committee

PHASE 3

Explore

▼
ObjectiveConduct Fit-to-Standard workshops, validate the SAP standard against requirements, capture deltas into the backlog, design integrations, extensions and data migration.

Key Activities

  • Fit-to-Standard (F2S) workshops by Line of Business
  • Demonstrate standard SAP Best Practices content
  • Capture gaps into Backlog in Cloud ALM
  • Design extensions (key-user, developer, side-by-side BTP)
  • Design integrations (Integration Suite / CPI)
  • Data migration mapping & approach
  • Security & Business Role design (S/4HANA roles)

Key Roles

  • Process Lead / Business Process Owner
  • Functional Consultants (per LoB)
  • Solution & Integration Architect
  • Extension Lead
  • Data Migration Lead
  • Security Lead

Public CloudStrict fit-to-standard — gaps must be addressed via standard config, key-user extensibility, or BTP side-by-side extensions. No classic ABAP development possible. SSB approves any deviation.
Private CloudAllows in-app key-user extensibility, classic ABAP (with care, on cloud-compatible "tier-2" model), plus BTP side-by-side. WRICEF still relevant but oriented toward clean core.
On-PremiseFull WRICEF (Workflow, Reports, Interfaces, Conversions, Enhancements, Forms). Maximum customization flexibility, but clean-core principles still recommended.
Quality Gate Q3 — Explore Exit F2S workshops complete · Backlog signed off · Solution & integration design approved · Data migration & security designs approved · SSB approved all deviations.
PHASE 4

Realize

▼
ObjectiveBuild the solution iteratively in sprints — configure, develop extensions, integrate, test, migrate data, train. Iterate until business sign-off (UAT).

Key Activities

  • Agile sprints (typically 2–4 weeks)
  • Configuration per backlog item
  • Extension / development build
  • Integration build & iFlow deployment
  • Data migration mock loads (typically 3 cycles)
  • Unit Test → String Test → SIT → UAT
  • Test automation (TAT in Cloud)
  • Training material development

Test Layers

  • Unit Test — by consultant / developer
  • String Test — end-to-end within process
  • SIT — cross-module & cross-system (e.g. SuccessFactors↔S/4, Ariba↔S/4, MM↔FI)
  • Regression / Automation — TAT or 3rd-party
  • UAT — business validation by key users
  • Performance / Load Test — pre-production

Quality Gate Q4 — Realize Exit All sprints complete · UAT signed off · All test layers passed · Data migration validated · Training materials approved · Cutover plan finalized.
PHASE 5

Deploy

▼
ObjectiveExecute the production cutover, go live, stabilize through hypercare.

Cutover Activities

  • Mock cutovers (typically 3 rehearsals)
  • End-user training & communications
  • Go/No-Go decision meeting
  • Final transports & deployment
  • Production data load (master + open transactions)
  • User & role provisioning
  • Production validation
  • Business sign-off & Go-Live

Hypercare

  • War room / command center
  • Daily status reports
  • Incident triage & resolution
  • Period-end close validation (first close)
  • Hypercare exit criteria review
  • Transition to AMS / steady state

Quality Gate Q5 — Deploy Exit Go-Live successful · Hypercare exit criteria met (incident volume normalized, first close completed) · AMS transition signed off.
PHASE 6

Run

▼
ObjectiveOperate the solution, adopt SAP releases, continuously improve, expand scope.

Run Activities

  • Incident, problem & change management (ITIL)
  • Release adoption & regression testing
  • Continuous improvement backlog
  • Periodic health checks (SAP EarlyWatch, etc.)
  • Roadmap reviews against SAP innovation pipeline
  • Roll-outs to additional countries / LoBs

Operational Reviews

  • Monthly Service Reviews
  • Quarterly Business Reviews
  • Yearly Roadmap Refresh
  • License optimization reviews

Public CloudTwo mandatory releases per year (1H, 2H). Regression test cycles required. New features auto-available; opt-in via SSB review.
Private CloudCustomer-scheduled upgrades (typically annual). FPS & SPS levels managed jointly with SAP. Greater control on timing.
On-PremiseCustomer fully controls release strategy & upgrade timing. SAP support lifecycle dates apply (mainstream maintenance 2040).
CROSS-CUTTING

Workstreams (span all 6 phases)

▼

SAP Activate workstreams run vertically across the 6 phases. Each has its own lead, deliverables and Q-Gate criteria.

Project Management

Governance, planning, RAID, status reporting

Solution / Architecture

Solution design, SSB, architecture decisions

Application Design & Configuration

F2S, configuration, business process docs

Custom Code / Extensibility

WRICEF (on-prem), key-user & BTP side-by-side

Integration

iFlows on Integration Suite, APIs, events

Data Migration

Mapping, mock loads, validation, sign-off

Testing

Strategy, scripts, evidence, automation

Security & Authorizations

S/4HANA Business Roles, IAS, IPS, segregation of duties

Organizational Change Mgmt (OCM)

Stakeholder, comms, training, adoption

Technical Infrastructure / Basis

System provisioning, transports, monitoring
